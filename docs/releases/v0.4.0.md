# rust-mirror 0.4.0

## Changes

- Mirror an organization-wide curated crate catalog with Cargo registry-dependency
  syntax, aliases, declared features, latest-N rules and exact pins.
- Resolve bounded native dependency closures without a Cargo binary at runtime.
  Preview counts, optional HEAD size estimates, budgets and inclusion explanations;
  approve the whole frozen plan before archive downloads.
- Fetch with bounded concurrency, retry notices, cancellation, resumable state and
  index-checksum verification. Emit an immutable static sparse registry with
  byte-preserved index lines and generation-local archive URLs.
- Retain older mirrored versions and protect crate generations during explicit
  whole-generation pruning. Publish schema 4 using the existing no-overwrite,
  preflight and marker-last rules.
- Expose catalog editing/paste diagnostics, preview/discovery/client-config APIs
  and additive protocol-1 completion, file-count and typed retry events.

## Upgrade

Rust/Cargo 1.90+ remains required. Existing toolchain inventory schemas 1/2/3 and
commands remain supported. Crate inventory schema 4 requires this version; older
readers refuse it. Frozen crate plans use their own schema 1. Protocol 1 remains
additive; Rust consumers matching public event variants exhaustively or constructing
expanded report structs may need updates. Use crate-aware retention for crate
leaves; toolchain pruning refuses them.

Direct `semver` and `serde_json` dependencies were owner-approved during native
crate design; they are new relative to published 0.3.0. No Cargo library, external
runtime Cargo, third-party solver or direct tar/flate2 dependency is introduced.
A fresh generation needs its eventual immutable HTTPS base URL before planning.
Configure Cargo source replacement explicitly; publication does not activate routing.

## Validation and limits

The [Phase 1 record](https://github.com/rustcommons/rust-mirror/blob/main/docs/evals/2026-11-13-crates-mvp.md)
identifies the qualified source and CI. The dated 100-root corpus had no exclusions:
186 native versions matched the Cargo lockfile union, with 45,125,358 archive bytes
on each side and 0% measured byte overfetch. Planning downloaded no archives.
These measurements describe that corpus, not all future catalogs.

Isolated HTTPS Cargo fetch/build/offline client checks ran on Linux, Windows and
macOS, building **itoa**, not all 100 crates or arbitrary foreign targets. Kill,
stdin-cancel and range-resume checks used a separate synthetic payload. Actual
disposable Nexus Raw schema-4 publication and Cargo consumption were proved on
**Linux only**, using a recorded legacy OSS test instance behind a verified TLS
proxy. This is neither production Nexus qualification nor a recommended server version.
Unchanged Phase 1 runtime evidence carries into this release candidate; release
package/install checks are recorded separately before merge.

Historical cohorts preserve their original index bytes and independent proofs.
The combined served index is replayed against historical/current profiles; if it
needs an unmirrored edge or exceeds resource bounds, planning **refuses** rather
than exposing an incomplete generation. This conservative refusal is an MVP limit.
Dev dependencies are excluded; enabled features, bounded profiles and all-platform
normal/build dependencies govern closure. No arbitrary Cargo completeness guarantee
or runtime build-safety/license/security review is implied by checksum verification.

Cargo.lock import, private/alternate registries, scheduling, in-generation compaction,
remote pruning and GUI work remain deferred. Upstream signatures are preserved,
not independently verified. Publication is owner-authorized; the coordinator merges
and uploads the qualified candidate before postpublication verification.
