# rust-mirror 0.5.0

## Changes

- Copy one or more Cargo.lock files into named, self-contained catalog pin sources
  with basename, original digest, import time and resolved edges. Preserve manual
  rules; preview replacement/removal diffs before explicit canonical writes.
- Support standard lock formats 1–4, including v1 metadata checksums. Report local/
  Git/unused entries and typed line/column refusals. Reject alternate registries,
  missing/conflicting checksums and ambiguous identities without partial writes.
- Mirror every exact locked registry package, including dev and target entries,
  checking its checksum against the index. Do not expand lock closure or invent
  feature profiles. Allow new yanked records only through exact lock pins.
- Add source-aware preview/explain, shared bounded input/name helpers and structured
  lock/manual/pinned retention reasons. Retain old frozen-plan/inventory readers.
- Fix repeated crate pruning: a valid completed receipt with its whole mirror
  absent is recognized as pruned, rather than paused work requiring a deleted
  predecessor. Private plans/receipts remain; partial/active runs stay conservative.

## Upgrade

Rust/Cargo 1.90+ remains required; no dependency additions or upgrades. Protocol 1
is unchanged, with additive command/stage/report fields. New writers use frozen-plan
schema 2 and crate-inventory schema 5. This version reads old schema 1/4; older
readers refuse new formats. Regenerate old crate prune previews (new wrapper schema 2).
Rust consumers constructing public structs or exhaustively matching enums may need
updates for source fields and `RunState::Pruned`.

Use the lock guide for `crates import-lock` / `remove-lock` and the public
`crates::lockfile` APIs. Imports copy data, never retain paths to reopen. Canonical
writes lose comments/formatting. A changed source observation changes plan identity;
existing whole-preview approval and frozen resume rules still apply. Removing a
source does not delete retained archives. Pruning leaves private workspaces intact.

## Validation and limits

The dated iteration record and exact PR checks identify source/tool/platform evidence.
The real-lock corpus pins ripgrep 12.1.1 (v1), rust-analyzer 2020-06-01 (v2), ripgrep
15.1.0 and fd 10.4.2 (v4); unit fixtures additionally cover v3 and refusals. It
contains 326 unique registry versions and 54,373,445 archive bytes, including five
initially observed yanked records. Planning makes zero archive GETs; exact lock
coverage is not a new native resolver completeness guarantee.

Qualification uses real Cargo fetch --locked followed by build --locked --offline
from isolated homes against a verified HTTPS registry on Linux and Windows. Build
scope is the named ripgrep/fd programs and rust-analyzer's `ra_hir_ty` package,
not every workspace package, feature or foreign target. Git checkouts are provisioned
independently; a missing-Git control refuses. Old upstream Chalk code emits
future-compatibility warnings under Rust 1.90; these results do not guarantee future
compiler compatibility. The non-build HomebrewFormula source links in ripgrep
archives are not extracted by the fixture.

Lockfiles do not carry feature/dependency-kind profiles or project sources. Git,
path/workspace data and native SDKs remain client responsibilities. Explicit
`external_sources_required` and skip reports prevent treating this registry as a
whole mixed-source project backup. Missing checksums (including legacy `<none>`),
unsupported index semantics, resource exhaustion or inconsistent served edges refuse;
no network repair, silent drops or synthetic closure expansion is attempted.
Existing historical-cohort refusal remains. Checksums/TLS are the trust model;
no independent signatures, redistribution/license approval, private registries,
production Nexus mutation or remote pruning is introduced.

Owner-authorized candidate: the coordinator merges and publishes after all gates,
then registry payload/docs.rs/fresh-install/tag/release verification records completion.
