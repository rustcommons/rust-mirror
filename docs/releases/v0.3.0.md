# rust-mirror 0.3.0

## Changes

- Configure corporate upstream HTTP CONNECT proxies, optional auth, NO_PROXY,
  explicit environment selection, additive CA PEM trust and connect/read timeouts.
- Diagnose ordered DNS/connect/proxy-auth/TLS/small-download stages and inspect CA
  or actually presented certificate subject/issuer/expiry/SHA-256 metadata.
- Opt in to advertised HEAD download estimates and aggregate sync progress/rate/ETA.
  Verification remains whole-file hash plus actual byte/path/resource bounds.
- Discover official stable versions/dates and dated beta/nightly releases, with
  bounded atomic caching, explicit refresh/offline modes and visible age/warnings.
- Extend public library APIs and protocol 1 without changing existing event meaning.
  Publishing remains separately configured and direct by default.

## Upgrade

Rust/Cargo 1.90+ remains required. Existing TOML without `[network]` remains valid;
Rust `Config` literals add `network: None`. Existing convenience functions remain.
Use `HttpsSource::with_network`, public `network` diagnostics, `selection::measure_sizes`,
`sync::run_with_options` and `releases::load`. Publishers opt in using
`preflight_with_network`/`publish_with_network`; upstream configuration is not
implicitly inherited. The owner approved `webpki-roots` direct access and
`x509-parser` 0.18 with default features disabled on 2026-11-12. Certificate parsing
is display-only; rustls makes every TLS trust decision.

## Validation and limits

See the dated qualification record for exact source/package/host and fixture evidence.
A local inspection proxy is a fixture, not a corporate-production deployment.
No TLS verification bypass, redirects, auto-trust or implicit proxy discovery is
provided. Proxy Basic auth over an HTTP proxy requires a trusted network/proxy.
SOCKS and IPv6-literal proxy endpoints are unsupported; IPv6 destination exclusions
are accepted. Socket deadlines do not bound a platform DNS resolver or replace
cooperative stop/watchdog semantics. Roots may not be sent in a TLS chain;
diagnostics describe only bounded received/parseable certificates.

HEAD lengths/rates/ETA are estimates, not integrity evidence. Release index presence
is not component/host/native execution proof. Cache hashes detect corruption rather
than provide independent upstream signatures. Resume validates the unchanged frozen
payload recipe while allowing explicit network configuration changes.
No production Nexus mutation/deletion, automatic retries, independent OpenPGP,
Cargo registry mirroring or new platform compatibility guarantee is introduced.
Publication is coordinated separately after owner confirmation.
