# rust-mirror 0.5.1

## Changes

Fix crate previews blocked by historical index versions that differ only in SemVer
build metadata. Unselected collisions now produce typed index_warnings instead of
rejecting the whole index. This covers the old ndk-sys 0.4.0 pair reached through
windowing dependencies while newer compatible versions are selected.

Selected, lock-pinned or retained normalized versions with different checksums
still refuse. Errors identify the crate, full versions, checksums and selected
version. Records are never merged; yank/requirement/feature exclusions and original
served-index bytes/order remain unchanged.

## Upgrade

No dependency additions/upgrades or runtime Cargo requirement. Rust 1.90 and protocol
1 remain unchanged. Saved schema 1/2 plans and schema 4/5 inventories keep their
identities when the new warning fields are empty. Frozen collision observations
require fresh whole-preview approval when they change; fetch/resume stays frozen.

New public types are crates::IndexWarning, IndexWarningKind and CollisionVersion.
Plan/FrozenPlan/Cohort/RetentionObservation add index_warnings; Rust struct-literal
callers must initialize the added fields. Older 0.5.0 strict readers refuse plans
with nonempty new fields: use 0.5.1 for planning and subsequent operations. Do not
rewrite historical approved plans or published archives.

## Validation and limits

The dated evidence identifies exact source and CI. Cargo 1.90 conformance covers
real ndk-sys metadata, synthetic yanked/non-yanked historical variants, a Bevy-style
Android dependency chain and the intentional stricter selected-checksum refusal.
Full-default winit 0.30.12 / eframe 0.31.1 plans are replayed through a byte-filtered
sparse registry; conformance lock generation requests no archives. This is metadata
resolution evidence, not builds of these GUI/game frameworks.

Manual, lock-only, retained, same-checksum and exact-version conflicts have targeted
regressions; legacy identity fixtures remain required. Existing Rust/Python, crate,
client, Nexus and native lifecycle gates continue to apply. Runtime budgets remain
unchanged. Warning groups/members/version strings are bounded; resource exhaustion
refuses instead of truncating. Unsupported semantics and ambiguous selected content
still refuse; no arbitrary-catalog completeness or production Nexus guarantee.

This owner-authorized candidate is published by the coordinator after review/merge
and qualification; registry/tag/docs.rs/postpublication evidence follows separately.
