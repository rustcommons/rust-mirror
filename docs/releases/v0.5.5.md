# rust-mirror 0.5.5

## Changes

This patch release updates locked dependencies. No rust-mirror source file changes:
every application and example file is byte-identical to 0.5.4. The CLI, event
protocol 1, saved schemas and the Rust 1.90 MSRV are unchanged.

| Dependency | 0.5.4 | 0.5.5 |
|---|---|---|
| sha2 (with digest, block-buffer, crypto-common) | 0.10.9 | 0.11.1 |
| toml (with toml_datetime, serde_spanned, winnow; toml_edit/toml_write replaced by toml_parser/toml_writer) | 0.8.23 | 1.2.2 |
| serde / serde_derive | 1.0.228 | 1.0.229 |
| tempfile | 3.23.0 | 3.27.0 |
| indexmap / hashbrown | 2.12.1 / 0.16.1 | 2.14.2 / 0.17.1 |
| webpki-roots (direct requirement) | 0.26 shim | 1.0 |

The TLS stack is the same as in 0.5.3 and 0.5.4: rustls 0.23.46, rustls-webpki
0.103.17 and webpki-roots 1.0.10. `ureq` still pulls the webpki-roots 0.26
compatibility shim, which re-exports the same 1.0 roots. No direct dependency is
added. In the locked graph, hybrid-array, const-oid, toml_parser and toml_writer
replace generic-array, version_check, toml_edit and toml_write.

**Library users:** the public field `rust_mirror::Error::report` has the type
`Option<toml::Value>`. With this release that is `toml` 1.x, not 0.8. Code that only
reads, clones or serializes the field is unaffected. Code that names the field's type
through its own `toml` 0.8 dependency must move to `toml` 1.

## Release assets

This is the first release whose GitHub assets include the signed provenance bundle
`rust-mirror-0.5.5.intoto.jsonl`. It sits next to the five native archives, the
Cargo CycloneDX SBOM and SHA256SUMS. The bundle holds the Sigstore-signed SLSA v1
build provenance for all seven of those files, one bundle per line. The release
workflow checks that it equals the attestation stored by GitHub before upload.
Verify downloads offline with
`gh attestation verify FILE --bundle rust-mirror-0.5.5.intoto.jsonl` and the policy
flags in the install guide. SHA256SUMS still lists the five archives and the SBOM
only, because the bundle signs SHA256SUMS itself.

Targets are unchanged: Windows (static CRT), GNU/Linux targeting glibc 2.17 via
cargo-libc 0.7.0, static musl Linux, macOS Apple Silicon and macOS Intel.
Windows and Apple executables are still not OS code-signed or notarized.

## Upgrade

Download the matching 0.5.5 archive, SBOM, SHA256SUMS and provenance bundle and
verify them as described in the install guide. Alternatively:

```sh
cargo install rust-mirror --version 0.5.5 --locked
```

No plan, catalog or mirror migration is needed.

## Validation and limits

Release qualification runs the Rust 1.90 checks, a clean package audit and an
exact-head dry run of all five targets. The dry run includes the eight GNU userland
launch and real HTTPS plan-sync gates, the SBOM and one six-entry SHA256SUMS.
It also stages a placeholder provenance bundle and verifies the stored bundle of
published 0.5.4 offline. A dry run cannot sign, so this release's own bundle,
attestations and SBOM bindings, and the downloaded Windows/GNU/musl runs, are
checked only after the tag and publication.

GNU evidence covers CentOS 7, AlmaLinux 8, openSUSE Leap 42.3, Ubuntu 16.04/18.04/20.04
and Debian 8/9 container userlands on modern hosted kernels. Old native kernels are
untested; use musl for glibc below 2.17. SBOM scope is the locked all-target Cargo
graph, not OS runtimes, SDKs or CI tools. Existing proxy/NSS, filesystem, client-build
and production-Nexus limits are unchanged.
