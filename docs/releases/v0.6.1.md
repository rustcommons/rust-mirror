# rust-mirror 0.6.1

## Changes

This patch fixes four product findings:

- The default publisher now matches the existing explicit-network path's bounded
  connect and per-socket-read/write idle timeouts. Progressing uploads/readbacks no
  longer hit the default path's total request deadline. Default limits are 180
  seconds; explicit network options set connect and idle limits separately. A peer
  trickling bytes can keep a request alive indefinitely: each read/write is bounded,
  with no overall time cap or minimum transfer rate.
- Crate downloads checkpoint after 8 MiB or 2 seconds of progress, and on
  completion, error or cancellation. This removes per-chunk shared receipt fsyncs.
  Each saved offset follows an archive fsync. Resume discards an uncommitted tail,
  revalidates the prefix and checks the final checksum. Staged completion clears the
  partial offset. If a staged crate later fails verification, its saved offset is
  durably reset before deletion, so a kill at that boundary cannot strand resume.
  Already spent transfer bytes stay counted when re-downloading.
- Incremental crate plans tolerate nonidentity upstream backfills such as
  `rust_version`, report typed `metadata_warnings` and serve the new upstream line
  in the successor. Each historical cohort proof keeps its original bytes.
  Changes to name, version, checksum, dependencies, features, features2 or links
  still refuse; checksums are never merged. Yank-only handling is unchanged.
- Toolchain sync `--resume`/`--force` and selected fetch resume accept the empty
  persistent prune lock after pruning.

No dependency changes. Rust 1.90 and CLI event protocol 1 remain unchanged.

## Upgrade

Install the matching archive or run:

```sh
cargo install rust-mirror --version 0.6.1 --locked
```

Private crate receipts migrate from schema 1 to schema 2 on resume. Continue that
workspace with 0.6.1; older binaries refuse schema 2. Frozen-plan JSON, public
struct fields and plan identities are unchanged for the same inputs. Historical
generations stay immutable. Library callers obtain typed diagnostics from the
additive `FrozenPlan::metadata_warnings()` method; its new warning types are
non-exhaustive. CLI previews/explanations and event command reports display these
computed diagnostics without persisting them in saved plans.

## Release pipeline and assets

This is the first real release through the standard phase 2 pipeline adopted
since 0.6.0. The isolated reusable builder builds and signs before the owner's
crates-io approval; publishing happens after approval, then the pipeline creates
and completes the draft-first GitHub Release and verifies publication. Nothing
compiles in the publish job. The token is minted last and scoped to publishing.
The archive README uses the strict attestation policy; SBOM/crate tooling runs
separately from binary collection. Fork PRs skip candidate builds. Latest status
uses numeric version ordering. See [the changelog](https://github.com/rustcommons/rust-mirror/blob/main/CHANGELOG.md).

Exactly nine assets: `rust-mirror-0.6.1.crate`, five native archives (Windows static
CRT, GNU/Linux glibc 2.17, static musl Linux, macOS arm64 and macOS x86_64),
`rust-mirror-0.6.1.cdx.json`, `SHA256SUMS` (seven entries) and
`rust-mirror-0.6.1.intoto.jsonl`. The bundle signs the crate, five archives, SBOM
and SHA256SUMS. Follow [install and verify](https://github.com/rustcommons/rust-mirror/blob/main/docs/INSTALL.md).
No OS signing/notarization is claimed.

## Validation and limits

Each product regression was observed failing before its fix and passing after.
The local throttled publisher fixture uses scaled idle windows; it is not a new
production-Nexus measurement. The crate test kills a real child after a durable
8 MiB checkpoint and an additional uncommitted 64 KiB, then checks the exact resume
offset, counters and final bytes. Interval boundaries, legacy migration, identity
refusals, historical proofs and post-prune reuse are also covered.

Release qualification requires Rust/Python checks, a clean package audit and the
exact-head five-target Trusted publishing dry run, including all eight GNU
userland gates, the crate, SBOM and single SHA256SUMS. Signing, owner approval and
the complete publication chain are checked only after the owner merges and tags.
See [candidate evidence](https://github.com/rustcommons/rust-mirror/blob/main/docs/evals/2026-11-22-release-0.6.1.md).

Checkpoints are checked on accepted writes; there is no background checkpoint
timer during a blocked network read. An abruptly killed run discards its
uncommitted tail, which is not in the persisted transfer counter. Disk/controller
power-loss durability remains unproved. A server can still store an upload and
then stall its response; inspect partial remote prefixes before retrying.
Existing client/Nexus, macOS public-download execution and old native-kernel gaps
remain. GNU gates qualify container userlands on modern kernels; use musl below
glibc 2.17. SBOM scope is the locked Cargo graph, not OS/SDK/CI tools.
