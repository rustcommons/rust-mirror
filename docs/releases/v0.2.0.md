# rust-mirror 0.2.0

## Changes

- Declare retention for pinned releases, latest stable versions, nightly windows,
  newest/rollback generations and explicit generation pins. Discover local runs,
  preview exact local folders/files/bytes and prune only with explicit apply.
- Add protocol-1 JSON lines with stages, artifacts, byte/hash progress, independent
  heartbeats and typed terminal outcomes for a loosely coupled GUI child process.
- Add library observers/cancel tokens and controlled operation variants. Initialized
  frozen fetch/sync state can resume after cooperative stop or process interruption.
- Add read-only publish preflight and observed upload/verification. Preflight does
  not reserve remote paths or prove later PUT permission; publication checks again.
- Keep README and docs.rs short, linking detailed operating and protocol guides.

## Upgrade

Use Rust/Cargo 1.90+ and `cargo install rust-mirror --version 0.2.0 --locked`.
Existing selection TOML without retention remains valid. Rust `Config` literals
need the optional `retention` field. Existing convenience library calls remain;
use `_with_control` variants for observed/cancellable operations. Only CLI events
are a versioned cross-process contract; library users should pin compatible versions.

GUI clients opt in with `--events jsonl`; `--cancel-stdin` enables cancel/EOF input.
Reject unsupported protocol majors. Drain stdout/stderr and use a local watchdog;
heartbeat is liveness/latest declared work, not proof of transfer progress.

## Validation and limits

Qualification/publication evidence is maintained separately at exact source revisions.
Cancellation is cooperative; a blocked synchronous syscall can wait until its timeout,
while heartbeats continue. A killed process/broken pipe may have no final result.
Assemble/rustup retain completed inputs but require a new output after interrupted
staging. Publish/prune are not rollback transactions; inspect partial outcomes.

Pruning removes whole local mirror roots, preserves private working state and binds
apply to a revalidated preview. Incomplete/locked/unknown runs and missing previous
dependencies refuse pruning. No in-generation compaction or Nexus deletion is added.
No Cargo registry mirroring, scheduler, independent OpenPGP verification, hostile/NFS
filesystem or blanket native/server compatibility guarantee is implied.
