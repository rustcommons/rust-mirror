# rust-mirror 0.5.4

## Changes

This is the first release whose prebuilt downloads carry the security-sensitive
locked dependency fixes already published in the **0.5.3 crate**. Version 0.5.3
is **crate-only**: its SBOM attestation failed before any binary upload. There
are no 0.5.3 prebuilt downloads. Older downloads do not acquire fixes when repository
locks change; use verified 0.5.4 downloads or a patched crate installation.

Release tooling now gives the Cargo CycloneDX SBOM a deterministic canonical UUID
serialNumber, required by the pinned attestation action. Five native archives and
the source-bound SBOM are covered by a single six-entry SHA256SUMS. All seven files
receive reusable-workflow provenance; each archive also receives an SBOM binding.
The intended profile is Windows static CRT, GNU/Linux glibc 2.17 via cargo-libc 0.7.0,
static musl Linux, macOS Apple Silicon and macOS Intel. Windows/Apple executables
remain unsigned by OS code-signing/notarization services.

No application implementation, locked dependency identity, CLI/library contract,
protocol 1, saved schema or Rust 1.90 MSRV changes from 0.5.3. Only the reported
package/tool version and packaged user documentation change. The SBOM tooling fix
was merged separately; no tag, source/signer guard or historical manifest is changed.

## Security

**Affected:** <=0.5.2 when installed with the shipped lock (--locked) or obtained
as a prebuilt download. **Patched crate:** 0.5.3. **First patched downloads:** 0.5.4.
The dependency graph is identical to 0.5.3: rustls 0.23.46, rustls-webpki 0.103.17,
webpki-roots 1.0.10 and rustix 1.1.6, with required existing libc/linux-raw-sys updates.
See the [complete RustSec/GHSA table and exposure analysis](https://github.com/rustcommons/rust-mirror/blob/main/docs/releases/v0.5.3.md#security).
These are inherited fixes, not additional vulnerabilities newly fixed by 0.5.4.

Fixed official upstream origins, TLS verification and the absence of session-secret
debug logging bound the observed exposure; they do not eliminate all attacks on
certificate validation. Configuration-specific Brotli/CRL/provider/xattr exclusions
and the lack of a demonstrated rust-mirror exploit remain as documented in 0.5.3.
Library consumers can unify different features and must update their own locks.

## Upgrade

Download the matching 0.5.4 archive, SBOM and SHA256SUMS and verify them as described
in the install guide. Alternatively:

```sh
cargo install rust-mirror --version 0.5.4 --locked
```

An already installed 0.5.3 crate has the same patched dependencies and need not be
replaced solely for the download fix. Omitting --locked is not an assurance of
safety. No plan/catalog migration is needed; do not disable TLS verification or
auto-trust presented certificates to work around an upgrade problem.

## Validation and limits

Release qualification requires clean source/dependency comparison, Rust 1.90 checks,
package audit and an exact-head five-target dry run, including all eight GNU
launch/real HTTPS plan-sync userland gates. The dry run exercises final SBOM
serialization, UUID validation, full lock checksums/source properties, the shared
archive collector and six-entry manifest. It does not obtain an OIDC token or claim
actual signing/upload. Real reusable signer/SBOM bindings and downloaded native
execution must pass after the owner-approved merged tag and publication.

The named patched-graph native/client/Nexus evidence carried from 0.5.3 retains its
original host, client, fixture and SDK limits. No unrelated heavy matrix is
requalified merely for the version/docs change. The candidate package is inspected
and installed from its unpacked bytes with a fresh Cargo home. Registry checksum/
payload, docs.rs, fresh registry installation, all seven public files, exact reusable
signer/source digests, all five archive SBOM bindings and public Windows/GNU/musl
runs are postpublication gates, not claims made by these notes in advance.

GNU evidence covers CentOS 7, AlmaLinux 8, openSUSE Leap 42.3, Ubuntu 16.04/18.04/20.04
and Debian 8/9 container userlands on modern hosted kernels. Old native kernels and
commercial SLES are untested; glibc below 2.17 should use musl. Native macOS build
smokes do not prove post-download Gatekeeper UI. SBOM scope is the locked all-target
Cargo graph, not OS runtimes, SDKs or CI tools. Existing proxy/NSS, hostile-filesystem,
arbitrary client-build and production-Nexus limits remain. No SLSA3 badge is claimed
before verification of this release's live reusable provenance.
