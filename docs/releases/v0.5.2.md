# rust-mirror 0.5.2

## Changes

This patch ships five prebuilt CLI downloads with one SHA256SUMS:

| Platform | Archive target |
| --- | --- |
| Windows, Intel/AMD 64-bit, static C runtime | x86_64-pc-windows-msvc (.zip) |
| Linux, dynamic glibc 2.17+ | x86_64-unknown-linux-gnu (.tar.gz) |
| Any x86_64 Linux, static musl | x86_64-unknown-linux-musl (.tar.gz) |
| macOS, Apple Silicon | aarch64-apple-darwin (.tar.gz) |
| macOS, Intel | x86_64-apple-darwin (.tar.gz) |

The new GNU download uses cargo-libc 0.7.0 pinned to
e68ca7bf3a8ffd973c8576acc48abd0fbcc66d25, targeting glibc 2.17.
Each GNU release build must launch and complete real HTTPS crate preview/approved
sync in CentOS 7, AlmaLinux 8, openSUSE Leap 42.3, Ubuntu 16.04/18.04/20.04 and
Debian 8/9 digest-pinned container userlands. GNU needs the documented dynamic
runtime libraries, including libgcc_s; choose musl to avoid those dependencies.

All five archives include LICENSE and README.txt. GitHub provenance attestations
cover every archive and the single SHA256SUMS. Windows uses static CRT: no Visual
C++ Redistributable is needed. Windows Authenticode and Apple signing/notarization
are absent; follow the install guide's checksum, provenance and unsigned-download
instructions. The README now offers binary downloads first, Cargo install second.
v0.5.1 retains its original four archives and original manifest without changes.

## Upgrade

No mirroring runtime logic changes from 0.5.1. Package/tool version reporting is
0.5.2; dependencies, Rust 1.90 MSRV, protocol 1, saved schemas and CLI/library
contracts are unchanged. No Cargo.lock regeneration or plan migration is required
by this distribution patch. Existing collision warnings/refusals and resource
bounds remain. Source installations continue to use cargo install --locked.

The existing Windows, musl and macOS build methods are unchanged. Tag-triggered
assets use the exact published source, --locked and the pinned Rust toolchain.
A read-only PR-candidate dry run qualifies the release before any tag or upload;
candidate builds cannot publish.

## Validation and limits

Release qualification requires five native platform builds and original/unpacked
version/protocol checks, Windows DLL/static-CRT audits, musl static linkage and real
DNS/TLS plan/sync plus private-CA resume checks, all eight GNU userland gates, and
verification of all five archive hashes against one sorted manifest. The package
audit compares clean VCS, source, normalized/original manifest, unchanged dependency
lock entries, README/changelog/license and allowed archive members. CI also checks
Rust tests/fmt/Clippy/rustdoc, Python refusal tests and a fresh installed package.

Historical runtime evidence is carried only because src/ bytes and dependency
identities match 0.5.1. The linked records retain bounded Cargo/client, four-host
Rustup and disposable Linux/Windows Nexus proofs; this release does not repeat
unchanged heavy matrices or broaden their scope. Postpublication registry, docs.rs,
installed package and actual public downloads require separate recorded evidence.

The GNU evidence covers **container userlands on a modern host kernel only**:
old native kernels are untested. Leap 42.3 is a community userland proxy, not
commercial SLES qualification. For **glibc below 2.17 use musl**. Normal CPU/kernel,
filesystem and DNS/proxy/NSS limits still apply; musl does not load glibc NSS plugins.
No universal enterprise/old-OS, arbitrary-project or production-Nexus guarantee.
