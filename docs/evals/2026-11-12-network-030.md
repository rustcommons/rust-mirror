## Proxy diagnostic/header regressions

A non-UTF-8 authentication realm reproduced an incorrect Network classification.
The probe now parses only the ASCII HTTP status line, leaving other header bytes
opaque, and retains strict status/protocol/size checks. The focused regression
passed after the fix. Temporary category-only debugging output was removed.

The GUI maintainer reported missing auth on ordinary ureq transfers. An explicit
credential-required regression with the reported test identity passed ordinary
GET, HEAD, range-attempt, resolve and every check-network stage. The fixture now
compares header names/auth scheme case-insensitively while comparing the Base64
credential token exactly. ureq emits lowercase `basic`; the manual probe uses
`Basic`, both valid under [RFC 9110 section 11.1](https://www.rfc-editor.org/rfc/rfc9110.html#section-11.1).
This is evidence that the tested transfer path sends credentials, not proof of the
GUI harness's behavior. The finding and retest branch were sent to its maintainer.

## GUI retest and Windows fixture correction

The GUI maintainer confirmed the missing-auth report was its harness's literal
`Basic` comparison and closed the report. On source `41948e5`, after correcting
only scheme matching, its worker passed check-network, 306,193,438 known bytes of
plan estimates (no unknowns), inspection TLS with an explicit CA and wrong-password
Auth refusal with dependent stages skipped. It observed 23 authenticated lowercase
`basic` CONNECTs, one successful capitalized probe and one wrong-password refusal;
no passwords appeared in its logs. These are maintainer-reported separate-harness
observations, not independently rerun or production evidence. The core regression
is retained and covers the normal source and CLI stdin paths.

Windows CI run `43156843217` failed because the environment fixture tried to set
uppercase/lowercase environment names independently. Windows treats these names
case-insensitively, so the later test setup replaced the intended value. The test
now exercises distinct case precedence only on case-sensitive systems and preserves
the documented HTTPS_PROXY versus ALL_PROXY precedence on Windows. The test-only
serialization guard recovers poison so one failed assertion does not obscure other
cases; product locking/refusal semantics are unchanged. Runtime/package source is
unchanged by this fixture/doc correction; native qualification remains bound to
source `3d86a14c161902bdf15cc10b69b7397f7c117c79`.

A late-cancellation regression also reproduced a successful HEAD size result after
a stop request arrived during blocked proxy I/O. The HEAD path now checks the
shared token immediately after the request returns, before propagating either a
size or transport failure. The focused regression requires typed Cancelled; no
files, frozen plans or resumable state are mutated by HEAD measurement.

The normal-transfer regression additionally reproduced rejection of a valid UPN
username (`alice@example.com`). The credential validator now permits `@` while
retaining Basic-auth's colon/control-character restriction. The credential-required
GET regression verifies the exact UPN token; no credentials are logged or persisted.

Malformed equals-form proxy flags also reproduced reflection of a forbidden test
userinfo URI in the hello/stage label. Session command labels now accept only known
command names, and unsupported proxy-option syntax is rejected with a constant
message before generic parsers can echo it. Regression coverage checks both leading
and post-command forms in JSON/diagnostics. This does not accept credential-bearing
argv or change any valid command name.
