## Behavior and focused cases

`discover` is metadata-only. It lists completed inventories plus completed,
in-progress, locked and unknown sync/fetch workspaces without claiming payload
verification or resume compatibility. `preview_directory` verifies candidates,
protects the caller's exact next-previous path and every matching paused-run
previous-inventory identity, and fingerprints managed directory content/state before
and after planning. Unknown/busy runs or missing dependencies refuse planning.
`apply` rechecks under known writer locks before unlinking any inventory marker.

Eleven added portable cases cover:

- Actual synthetic-fixture sync layout plus selected snapshots and paused-state discovery.
- Exact next-previous protection even when old, newest-count and generation pins,
  paused dependency protection and exact per-folder byte accounting.
- Changed private state/content, restored bytes with changed metadata and new immediate
  directory entries refusing apply before any inventory deletion.
- Locked, unknown and missing-previous runs refusing planning; read-only discovery
  still exposes their conservative states/issues.
- A completed marker without its committed sync report protected as in-progress;
  explicit-root planning refuses it and directory apply preserves its private state.
- Serializable CLI catalogs and directory previews.
- Same-build Serde round trips for explicit/directory plans, version/envelope checks
  and modified-preview refusal before any inventory deletion.
- A run becoming locked after preview, and changed paused state refusing apply.
- Refusing discovery of a managed workspace as a directory, and refusing explicit
  private `.sync`/`.download` snapshot roots even when their inventories are valid.
- A direct snapshot named `mirror` retaining discovery boundaries and preserving
  unrelated directory trees, including an untraversed Unix symlink fixture.

The earlier lock fixture intentionally creates a sync lock in a fetch workspace;
that temporary lock is now removed after the refusal check. Leaving mixed sync/fetch
markers behind correctly makes the workspace unknown rather than granting deletion.

## Deferrals and boundaries

- Whole private sync/fetch workspace cleanup is deferred. Only completed mirror
  roots are deletion candidates; caches, plans, reports, incomplete runs and enclosing
  folders remain. No new pruning lock file is created inside a paused workspace;
  apply can acquire its existing writer lock to freeze inspection.
- General progress/cancel observers, typed cancelled errors, heartbeats and the
  common EVENTS serializer are deferred to the library-wide design. Existing
  retention entry points can remain wrappers around future observer-aware variants.
  This work does not establish a subprocess or JSON-lines protocol.
- Managed content is hashed and file metadata is bound; access times, managed-directory
  mtimes and empty regular pruning lock files are intentionally excluded. Unmanaged
  entries are bound shallowly by name/type/metadata; their contents and paths outside
  the explicitly selected directory are never traversed and are outside the binding.
- Discovery stops at immediate children. Planning limits are 32 completed roots,
  300,000 managed entries, depth 64, 100 GiB per fingerprint and 512 MiB per file.
  Unknown layouts/links/resource excess refuse pruning instead of bypassing checks.
- Inventory mtime orders keep-newest policy; it does not identify active routing.
  The exact next-previous anchor must come from the selected/returned mirror path.
  Missing paused dependencies outside the discovery directory require explicit
  restoration/reorganization, not an implicit skip.
- Advisory locks freeze known workspaces only. New writers after preflight,
  publishers/readers, hostile filesystems and shared-machine/NFS operation still
  require the documented exclusive-maintenance boundary. No transactional rollback
  or durable recovery report is promised after process termination.
- Nexus-side pruning and 0.2.0 publication remain deferred/separately authorized.
