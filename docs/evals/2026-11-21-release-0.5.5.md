## Library compatibility note

`rust_mirror::Error` is re-exported and has the public field
`report: Option<toml::Value>`, so the toml 0.8→1 move changes a type that library
users can name. Under Cargo SemVer that is a breaking change for code that names
`toml` 0.8's `Value` through that field. Code that only reads, clones or serializes it
is unaffected. The only crates.io reverse dependency, rust-mirror-gui (`^0.5.4`), uses
`.report` without naming toml types. The notes and changelog state this; choosing
0.5.5 over 0.6.0 is the owner's authorized decision, flagged to the coordinator.

## Binary candidate and remaining evidence

The exact-head release-binaries candidate dry run must pass all five native builds,
all eight GNU userland launch and real HTTPS plan-sync gates, the SBOM and one
six-entry SHA256SUMS, and the `provenance-dry-run` job. That job stages a placeholder
bundle and verifies published 0.5.4's stored bundle offline. Run IDs are in the PR.

0.5.5 is the first release whose live upload attaches
`rust-mirror-0.5.5.intoto.jsonl` (`has_provenance_asset` is true from 0.5.5). A dry
run cannot sign, so the live bundle, its match with GitHub's attestation store, the
SBOM bindings, registry/docs.rs/install and public Windows/GNU/musl execution are
post-tag gates. crates.io returned 404 for 0.5.5 before release. No publication is
claimed here.
