## Initial CI correction

The first candidate (`5be755a`, dry run 44983139181) exposed a Windows handle
permission error in checkpointing: `set_len` is not permitted on an append-only
handle. Windows crate fetch tests and client qualifications failed with Access
Denied; Ubuntu core CI was cancelled by the matrix's fail-fast behavior. The
Windows Nexus hard-kill fixture also stopped before reaching its kill point.
The download handle now opens for writing and seeks to the exact saved offset
under the existing workspace lock, so checkpoint truncation works on Windows.
The real Windows Nexus fixture previously killed at the first 64 KiB and assumed
all on-disk bytes were resumable. It now waits for a transfer lasting beyond the
checkpoint interval, kills the real process, reads the stopped receipt and checks
that actual resume events use those exact nonzero durable offsets. The synthetic
TLS fixture also checks exact saved offsets. A local real-CLI run passed with
kill-before-checkpoint offset 0 and graceful-cancellation offset 65,536; each
resumed generation verified all 1,048,576 synthetic payload bytes, rate-limit notice
and blocked-read heartbeats. This is fixture evidence, not actual Nexus evidence.
The corrected head must pass fresh full CI and the complete dry run; the initial
failures are retained here rather than retried without a fix.

## Staged recovery review correction

Owner review of `3951688` found a stale full-length offset after `.part` was
renamed to `.crate`. If the staged file was then corrupted, deleting it left a
nonzero receipt with no partial, permanently refusing resume. The new staged-file
regression reproduced the exact "partial crate is shorter than its durable
receipt" error before correction. The unchanged natural-corruption case also passed
with `fetch.rs` from base `485ca95` and failed with that file from `3951688`; this
is a scoped implementation comparison, not fresh qualification of either old tree.
Successful staging now clears the partial offset;
recovery also durably resets any older saved offset BEFORE deleting a bad staged
file. Previously spent network bytes remain charged to the transfer budget.

A real child-process kill test pauses through the ordinary restart observer after
the durable reset and before deletion. The parent kills it, verifies the corrupt
staged file still exists with saved offset zero, then resumes and requires a fresh
successful download and exact inventory. The test injects the full-length receipt
left by the reviewed head, so recovery of existing paused work stays covered.

A focused `features2` identity regression uses two independently valid schema-2
index records whose unactivated features differ. It requires an Integrity refusal
only when retaining the predecessor. Removing `features2` from `IDENTITY_FIELDS`
was tested locally: the regression failed; restoring the guard makes it pass.
This avoids the earlier broad test's invalid schema-1/features2 rejection.

Changelog/notes now accurately identify the default timeout change as matching the
existing explicit-network path. Both only bound individual reads/writes: a
trickling peer has no overall time cap or minimum transfer rate.

The corrected full local suite passed 205 Rust tests and 75 Python tests. The final
natural-corruption case passed separately after its legacy-receipt injection was
moved exclusively to the kill-boundary test. fmt, Clippy, warning-denied rustdoc,
release-doc and action-pin checks passed. The existing pinned local API checker
again reported `184 checks: 184 pass, 16 skip` and `no semver update required`
against published 0.6.0. No dependency, public API or CI configuration changes.
